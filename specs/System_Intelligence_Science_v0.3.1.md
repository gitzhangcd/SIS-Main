# Part I｜Scientific Identity

# 1｜SIS 研究的不是 Agent

System Intelligence Science 不以：

```text
Agent
Multi-Agent
RAG
Workflow
Planner
Verifier
Memory
Tool Use
Harness
```

作为第一性科学对象。

这些对象可以非常重要，但属于某个技术时期的实现形式。

一个科学母问题必须在这些实现名称消失以后仍然成立。

因此冻结：

$$
\boxed{
ImplementationForm
\neq
ScientificPrimitive
}
$$

SIS 的研究对象是：

$$
\boxed{
CompositeIntelligentSystem
}
$$

即：

> 一个由一个或多个能力承载组件构成，在给定任务、环境、信息、资源、约束和风险条件下，通过组件关系、内部状态、观察、控制和动态交互产生系统级行为与系统级性质的智能系统。

这一 Scientific Identity 继承自 v0.2。

---

# 2｜SIS 第一性母问题

正式冻结：

$$
\boxed{
\begin{aligned}
&\text{Given a task distribution, environment, information state,}\\
&\text{resource budget, constraints and risk conditions,}\\
&\text{how do capability-bearing components, their organization,}\\
&\text{system state, observability, control and adaptation}\\
&\text{jointly determine the achievable system-level capability}\\
&\text{frontier, viability, robustness and adaptability?}\\
&\\
&\text{Under what conditions are these relationships causal,}\\
&\text{generalizable and transferable?}
\end{aligned}
}
$$

中文：

> **在给定任务分布、环境、信息条件、资源预算、约束与风险条件下，一个由能力单元构成的智能系统，其组件能力、组织关系、内部状态、可观察性、控制机制和适应过程，如何共同决定系统可实现的能力前沿、可行性、鲁棒性与适应能力；这些关系又在何种条件下具有因果性、可泛化性与可迁移性？**

该问题继续取代：

> 怎样设计一个更强的 Agent？

以及：

> 多 Agent 是否优于单 Agent？

等实现层问题。

---

# 3｜SIS 是研究纲领，不是架构处方

SIS 不预设：

$$
System>Component
$$

不预设：

$$
ComplexSystem>SimpleSystem
$$

不预设：

$$
MultiAgent>SingleAgent
$$

不预设：

$$
Adaptive>Static
$$

也不预设：

$$

$$

它规定的是：

> 这些关系应该如何定义、操纵、测量、证伪、限定边界并检验迁移。

因此：

$$
\boxed{
SIS
=
ResearchProgram
}
$$

而不是：

$$
\boxed{
ArchitectureRecipe
}
$$

# Part III｜First-Principles Scientific Ontology

# 5｜Layer 0：Context

定义：

$$
\boxed{
\Omega
=
Task
+
Environment
+
Information
+
Budget
+
Constraints
+
Risk
}
$$

System capability 必须始终被理解为：

$$
\boxed{
Capability(\mathcal S\mid\Omega)
}
$$

而不是系统自身脱离条件的固定常数。

---

# 6｜Layer 1：Primitive System

在时间 \(t\)：

$$
\boxed{
\mathcal S_t
=
(
\mathcal C,
\mathcal R_t,
X_t,
O_t,
\pi_t
)
}
$$

其中：

* \(\mathcal C\)：Components；
* \(\mathcal R_t\)：Relations；
* \(X_t\)：System State；
* \(O_t\)：Observation；
* \(\pi_t\)：Control / Policy。

其演化通过：

$$
\boxed{
Dynamics
}
$$

描述。

---

# 7｜Component

Component 是能够承担某种能力或系统功能的单元。

可以是：

```text
language model
vision model
retriever
database
tool
human expert
rule engine
planner
sensor
external service
memory subsystem
```

但 SIS 不把其中任何具体类别冻结为必备组件。

---

# 8｜Relation

Relation 描述组件之间：

```text
information flow
dependency
authority
control
message passing
shared resource
shared memory
fallback
verification
coordination
```

Architecture 因此是：

$$
\boxed{
\mathcal A_t
=
\Gamma(
\mathcal C,
\mathcal R_t
)
}
$$

而不是独立 primitive。

---

# 9｜State ≠ Observation

定义：

$$
X_t
=
ActualSystemState
$$

$$
O_t
=
ObservedInformationAboutState
$$

冻结：

$$
\boxed{
X_t
\neq
O_t
}
$$

因此 SIS 可以研究：

```text
partial observability
hidden failures
missing telemetry
diagnostic uncertainty
delayed detection
```

---

# 10｜Control

Control 描述：

> 系统如何根据当前可用信息选择行动、资源分配或系统变化。

可写为：

$$
\boxed{
U_t
=
\pi(
H_t
)
}
$$

其中 \(H_t\) 为合法可获得的 observation / information history。

# Part IV｜Mechanisms, Processes and Properties

# 11｜Mechanism

Mechanism 是可操作、可比较、可形成因果假设的系统作用结构。

例如：

```text

routing
delegation
consensus
redundancy
specialization
memory externalization
state externalization
active probing
human escalation
fault isolation
resource reallocation
predictive regulation
```

Mechanism 不是 final outcome。

---

# 12｜Process

Process 描述系统中随时间发生的过程，例如：

```text
coordination
failure propagation
diagnosis
recovery
reconfiguration
adaptation
learning

```

冻结：

$$
\boxed{
Mechanism
\neq
Process
\neq
Property
}
$$

---

# 14｜Capability Frontier

SIS 不应仅以单个 score 定义系统能力。

更一般地：

$$
\boxed{
\mathcal P_{sys}
=
\{
Y:
Y
\text{ achievable under } \Omega
\}
}
$$

因此系统可以存在：

```text

accuracy–latency trade-off
capability–risk trade-off
reliability–resource trade-off
```

---

# 15｜Efficiency

Efficiency 表示：

$$
\boxed{
Outcome
/
ResourceUse
}
$$

但具体形式不冻结。

---

# 16｜Viability

Viability 表示：

> 系统是否能够维持在允许的运行区域内。

定义 viable region：

$$
\mathcal V
$$

要求：

$$
X_t
\in
\mathcal V
$$

在相关时间尺度上成立。

因此：

$$
HighPerformance
\not\Rightarrow
Viability
$$

---

# 17｜Robustness

Robustness 表示：

> 系统在扰动、错误、组件失败或环境变化下维持功能的能力。

它是 property。

不是：

$$
Program
$$

---

# 18｜Adaptation 与 Adaptability

Adaptation：

$$
\boxed{
Process
}
$$

Adaptability：

$$
\boxed{
Property
}
$$

因此：

$$
\boxed{
Adaptation
\neq
Adaptability
}
$$

其中：

* \(\mathcal A_t\)：architecture / relation state；

# 20｜Trajectory-Level Intelligence

定义：

$$
\boxed{

=
(

\dots,

```text

adaptation

```

v0.2 已要求实际执行至少保留 Event、StateTransition、Observation、Action 与 Outcome 的 ordered lineage。

$$

)
}
$$

避免将 path dependence 误写为当前状态效应。

迁移后表现仍好。

\rightarrow

该区分继承自 v0.2。

}
$$

# 46｜Routing Status

Canonical enum：

```text
ROUTED
DESCRIPTIVE_ONLY
ROUTING_UNRESOLVED
SCIENTIFIC_NONCONFORMANT
```

---

# 47｜ROUTED

Scientific question、estimand 与 evidence 足以支持 Program classification。

要求：

```text
primary_program != null
```

---

# 48｜DESCRIPTIVE_ONLY

证据只能支持：

```text
what exists
architecture description
frequency
performance difference
association
```

例如：

$$
System_A=82
$$

$$
System_B=78
$$

但无法说明：

```text
what changed
what was held constant
mechanism
resource difference
information difference
```

则最多属于 descriptive / performance evidence。

v0.2 已明确这样的 score-only comparison 最高只能支持 CL1 Performance Comparison。

---

# 49｜ROUTING_UNRESOLVED

当 primary estimand 无法恢复时使用。

例如：

> Adaptive architecture outperformed static architecture.

如果无法判断其研究的是：

```text
static mechanism effect
trajectory effect
policy value
```

则：

$$
\boxed{
ROUTING\_UNRESOLVED
}
$$

---

# 50｜SCIENTIFIC_NONCONFORMANT

实验声称 causal / mechanistic conclusion，

但存在关键缺陷，例如：

```text
resource confounding
information confounding
no causal contrast
missing manipulation check
post-treatment leakage
invalid temporal ordering
missing trajectory for dynamic claim
```

则记录：

$$
\boxed{
SCIENTIFIC\_NONCONFORMANT
}
$$

这本身是一种有意义的 scientific evidence-quality state。

$$
\boxed{

\approx

=

$$

\rightarrow

# Part XIII｜Information Causality

# 57｜Information Typing

定义：

$$
\boxed{

=
(

O_t,
I^{probe}_t,
I^{derived}_t
)
}
$$

其中：

* \(I^{task}\)：pre-treatment task information；
* \(O_t\)：runtime observation；
* \(I^{probe}_t\)：active query / verification / probing 获得的信息；
* \(I^{derived}_t\)：reasoning / diagnosis / aggregation 得出的信息。

默认实验匹配：

$$
\boxed{
I^{task}_T
\approx
I^{task}_C
}
$$

不能把 treatment 后合法产生的 probe information 全部当 baseline confounder 消除。

# Part XIV｜Intervention Science

# 58｜Intervention ≠ Mechanism

Mechanism 是科学解释对象。

Intervention 是：

> 用于改变 mechanism 或相关 variable 的实验操作。

因此：

$$
\boxed{
Intervention
\neq
Mechanism
}
$$

例如：

```text
changed prompt
added verifier
changed topology
introduced retrieval
```

只是 intervention。

仍需说明其目标 mechanism。

---

# 59｜Manipulation Check

所有 causal intervention 必须问：

> intervention 是否真正改变了 target mechanism？

因此：

$$
\boxed{
Intervention
\Rightarrow
ManipulationCheck
}
$$

---

# 60｜Static 与 Dynamic Intervention

Intervention 可以：

```text
one-shot
scheduled
state-triggered
history-dependent
policy-generated
```

若 treatment 随 history 改变：

$$
U_t
=
\pi(H_t)
$$

则 identification 需要考虑动态 treatment semantics。

\rightarrow

$$

\not\rightarrow

$$

# Part XVII-A｜Human Reference & Evaluation Semantics

# 68A｜Reference 是评价对象，不是 latent truth 的同义词

定义 evaluator reference：

$$
\boxed{
R^{ref}_{q,c,v}
}
$$

其中：

```text
q  target evaluation question / scientific function
c  reference-construction conditions
v  reference version
```

Reference 的科学用途是：

```text
evaluation
calibration
benchmarking
adjudication support
decision-quality assessment
```

而不是宣称：

$$
Reference=WorldTruth
$$

因此冻结：

$$
\boxed{
EvaluatorReference
\neq
LatentTruth
}
$$

---

# 68B｜Expert Judgment 的 epistemic status

领域专家可以提供：

```text
observation interpretation
professional judgment
acceptable action boundaries
risk assessment
uncertainty characterization
adjudication
```

但：

$$
\boxed{
ExpertJudgment
\neq
LatentTruth
}
$$

Expert judgment 可作为：

```text
measurement evidence
reference-construction evidence
evaluation evidence input
```

其 scientific value 取决于：

```text
information available
expertise relevance
independence
evidence anchoring
uncertainty
adjudication
versioning
```

而不是仅由：

```text
expert title
institution
seniority
```

决定。

---

# 68C｜Expert Agreement ≠ Reference Validity

多个专家一致：

$$
Agreement\uparrow
$$

可以提高某些 reliability construct。

但不能直接推出：

$$
Validity=1
$$

因此：

$$
\boxed{
ExpertAgreement
\neq
ReferenceValidity
}
$$

Reference validity 仍需结合：

```text
construct definition
information boundary
evidence quality
measurement validity
temporal integrity
external validation where available
```

判断。

---

# 68D｜Reference Uncertainty

正式冻结：

$$
\boxed{
Reference
\not\Rightarrow
ZeroUncertainty
}
$$

Reference 可以显式携带：

```text
measurement uncertainty
expert disagreement
evidence gap
conditionality
acceptable variation
unresolved branch
mapping ambiguity
```

因此 benchmark 不得默认：

$$
ReferenceUncertainty=0
$$

---

# 68E｜Ex-Ante 与 Ex-Post Evidence Separation

当 reference 用于评价决策：

$$
\boxed{
ExAnteDecisionEvaluation
\neq
ExPostOutcomeValidation
}
$$

Ex-ante evaluator 应根据：

```text
decision-time information
admissible action set
risk / constraint state
available evidence
```

评价。

Ex-post evidence 可用于：

```text
outcome validation
retrospective mechanism analysis
calibration
longitudinal validation
```

但不得自动重写 prior decision correctness。

---

# 68F｜Hindsight Leakage

现有 Decision-Time Evidence Integrity 继续冻结：

$$
EvidenceTime
\leq
DecisionPoint
$$

R5 进一步定义 evaluator-side：

$$
\boxed{
HindsightLeakage
}
$$

若：

```text
future outcome / future evidence
```

虽未直接进入 system input，

但通过 evaluator / annotator 的已知结局：

```text
retroactively changes ex-ante reference
without legitimate ex-ante evidence path
```

则视为 hindsight contamination risk。

必须记录：

```text
future_information_known
blinding_status
hindsight_risk
mitigation
```

---

# 68G｜Reference Evidence Role Non-Inflation

R5 不新增第四类 Core evidence role。

仍保持：

$$
E
=
(
E^{opt},
E^{meas},
E^{val}
)
$$

Expert annotation 可作为：

$$
E^{meas}
$$

或 reference-construction input。

Adjudicated reference：

$$
\not\Rightarrow
E^{val}
$$

除非其确实满足目标 validation claim 的 evidence contract。

# Part XIX-A｜Decision Reference Semantics

$$

```text

risk
constraints
policy
decision evidence
```

```text

```

因此：

$$
\boxed{

\not\Rightarrow

}
$$

$$

