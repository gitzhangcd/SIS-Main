# Part I｜Scientific Identity

# 1｜SIS 研究的不是 Agent

System Intelligence Science 不以：

```text
Agent
Multi-Agent
RAG
Workflow
Planner
Verifier
Memory
Tool Use
Harness
```

作为第一性科学对象。

这些对象可以非常重要，但属于某个技术时期的实现形式。

一个科学母问题必须在这些实现名称消失以后仍然成立。

因此冻结：

$$
\boxed{
ImplementationForm
\neq
ScientificPrimitive
}
$$

SIS 的研究对象是：

$$
\boxed{
CompositeIntelligentSystem
}
$$

即：

> 一个由一个或多个能力承载组件构成，在给定任务、环境、信息、资源、约束和风险条件下，通过组件关系、内部状态、观察、控制和动态交互产生系统级行为与系统级性质的智能系统。

这一 Scientific Identity 继承自 v0.2。

---

# 2｜SIS 第一性母问题

正式冻结：

$$
\boxed{
\begin{aligned}
&\text{Given a task distribution, environment, information state,}\\
&\text{resource budget, constraints and risk conditions,}\\
&\text{how do capability-bearing components, their organization,}\\
&\text{system state, observability, control and adaptation}\\
&\text{jointly determine the achievable system-level capability}\\
&\text{frontier, viability, robustness and adaptability?}\\
&\\
&\text{Under what conditions are these relationships causal,}\\
&\text{generalizable and transferable?}
\end{aligned}
}
$$

中文：

> **在给定任务分布、环境、信息条件、资源预算、约束与风险条件下，一个由能力单元构成的智能系统，其组件能力、组织关系、内部状态、可观察性、控制机制和适应过程，如何共同决定系统可实现的能力前沿、可行性、鲁棒性与适应能力；这些关系又在何种条件下具有因果性、可泛化性与可迁移性？**

该问题继续取代：

> 怎样设计一个更强的 Agent？

以及：

> 多 Agent 是否优于单 Agent？

等实现层问题。

---

# 3｜SIS 是研究纲领，不是架构处方

SIS 不预设：

$$
System>Component
$$

不预设：

$$
ComplexSystem>SimpleSystem
$$

不预设：

$$
MultiAgent>SingleAgent
$$

不预设：

$$
Adaptive>Static
$$

也不预设：

$$
MoreObservability>LessObservability
$$

它规定的是：

> 这些关系应该如何定义、操纵、测量、证伪、限定边界并检验迁移。

因此：

$$
\boxed{
SIS
=
ResearchProgram
}
$$

而不是：

$$
\boxed{
ArchitectureRecipe
}
$$

# Part III｜First-Principles Scientific Ontology

# 5｜Layer 0：Context

定义：

$$
\boxed{
\Omega
=
Task
+
Environment
+
Information
+
Budget
+
Constraints
+
Risk
}
$$

System capability 必须始终被理解为：

$$
\boxed{
Capability(\mathcal S\mid\Omega)
}
$$

而不是系统自身脱离条件的固定常数。

---

# 6｜Layer 1：Primitive System

在时间 \(t\)：

$$
\boxed{
\mathcal S_t
=
(
\mathcal C,
\mathcal R_t,
X_t,
O_t,
\pi_t
)
}
$$

其中：

* \(\mathcal C\)：Components；
* \(\mathcal R_t\)：Relations；
* \(X_t\)：System State；
* \(O_t\)：Observation；
* \(\pi_t\)：Control / Policy。

其演化通过：

$$
\boxed{
Dynamics
}
$$

描述。

---

# 7｜Component

Component 是能够承担某种能力或系统功能的单元。

可以是：

```text
language model
vision model
retriever
database
tool
human expert
rule engine
planner
sensor
external service
memory subsystem
```

但 SIS 不把其中任何具体类别冻结为必备组件。

---

# 8｜Relation

Relation 描述组件之间：

```text
information flow
dependency
authority
control
message passing
shared resource
shared memory
fallback
verification
coordination
```

Architecture 因此是：

$$
\boxed{
\mathcal A_t
=
\Gamma(
\mathcal C,
\mathcal R_t
)
}
$$

而不是独立 primitive。

---

# 9｜State ≠ Observation

定义：

$$
X_t
=
ActualSystemState
$$

$$
O_t
=
ObservedInformationAboutState
$$

冻结：

$$
\boxed{
X_t
\neq
O_t
}
$$

因此 SIS 可以研究：

```text
partial observability
hidden failures
missing telemetry
diagnostic uncertainty
delayed detection
```

---

# 10｜Control

Control 描述：

> 系统如何根据当前可用信息选择行动、资源分配或系统变化。

可写为：

$$
\boxed{
U_t
=
\pi(
H_t
)
}
$$

其中 \(H_t\) 为合法可获得的 observation / information history。

# Part IV｜Mechanisms, Processes and Properties

# 11｜Mechanism

Mechanism 是可操作、可比较、可形成因果假设的系统作用结构。

例如：

```text
verification
retrieval
routing
delegation
consensus
redundancy
specialization
memory externalization
state externalization
active probing
human escalation
fault isolation
resource reallocation
predictive regulation
```

Mechanism 不是 final outcome。

---

# 12｜Process

Process 描述系统中随时间发生的过程，例如：

```text
coordination
failure propagation
diagnosis
recovery
reconfiguration
adaptation
learning
regulation
```

冻结：

$$
\boxed{
Mechanism
\neq
Process
\neq
Property
}
$$

---

# 13｜System Properties

SIS 主要研究：

$$
\boxed{

=
(

Viability,
Robustness,

)
}
$$

# 14｜Capability Frontier

SIS 不应仅以单个 score 定义系统能力。

更一般地：

$$
\boxed{
\mathcal P_{sys}
=
\{
Y:
Y
\text{ achievable under } \Omega
\}
}
$$

因此系统可以存在：

```text
performance–cost trade-off
accuracy–latency trade-off
capability–risk trade-off
reliability–resource trade-off
```

---

# 15｜Efficiency

Efficiency 表示：

$$
\boxed{
Outcome
/
ResourceUse
}
$$

但具体形式不冻结。

---

# 16｜Viability

Viability 表示：

> 系统是否能够维持在允许的运行区域内。

定义 viable region：

$$
\mathcal V
$$

要求：

$$
X_t
\in
\mathcal V
$$

在相关时间尺度上成立。

因此：

$$
HighPerformance
\not\Rightarrow
Viability
$$

---

# 17｜Robustness

Robustness 表示：

> 系统在扰动、错误、组件失败或环境变化下维持功能的能力。

它是 property。

不是：

$$
Program
$$

---

# 18｜Adaptation 与 Adaptability

Adaptation：

$$
\boxed{
Process
}
$$

Adaptability：

$$
\boxed{
Property
}
$$

因此：

$$
\boxed{
Adaptation
\neq
Adaptability
}
$$

# Part V｜Dynamic-System Semantics

# 19｜状态动力学

SIS 不把智能系统仅视作静态函数：

$$

\rightarrow

$$

而是：

$$
\boxed{
X_{t+1}
=
F(
X_t,
E_t,
U_t,
\mathcal A_t,
\xi_t
)
}
$$

其中：

* \(E_t\)：environment；
* \(U_t\)：action / intervention；
* \(\mathcal A_t\)：architecture / relation state；
* \(\xi_t\)：uncontrolled variation。

---

# 20｜Trajectory-Level Intelligence

定义：

$$
\boxed{
\tau
=
(
X_0,O_0,U_0,
X_1,O_1,U_1,
\dots,
X_T,Y_T
)
}
$$

动态系统研究必须保留 trajectory。

否则无法可靠研究：

```text

recovery
adaptation
reconfiguration
intervention timing
long-horizon degradation
```

v0.2 已要求实际执行至少保留 Event、StateTransition、Observation、Action 与 Outcome 的 ordered lineage。

---

# 21｜History Dependence

若：

$$
P(
X_{t+1}\mid X_t
)
$$

不足以描述系统，则必须显式建模：

$$
\boxed{
P(
X_{t+1}
\mid
X_{\leq t},
U_{\leq t}
)
}
$$

避免将 path dependence 误写为当前状态效应。

# 38｜Generalization 四级区分

冻结：

$$
\boxed{
Replication
\neq
PerformanceTransfer
\neq
CausalTransportability
\neq
MechanismInvariance
}
$$

其中：

### Replication

相同或近似 context 中重新得到 effect。

### Performance Transfer

某资产：

```text
prompt
workflow
skill
memory
policy
```

迁移后表现仍好。

### Causal Transportability

$$
do(M)\rightarrow Y
$$

从 source context 到 target context 仍成立，或变化能够由 boundary differences 解释。

### Mechanism Invariance

$$
M
\rightarrow
Z
\rightarrow
Y
$$

的关键 causal pathway 在 context change 后保持。

该区分继承自 v0.2。

\boxed{

# Part XIV｜Intervention Science
