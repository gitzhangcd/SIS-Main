## 2. Minimal candidate F0–F3 scientific *change-locus* classification

| Review candidate | Necessary actual difference | Scientific guard |
|---|---|---|
| **F0 · Ephemeral episode adjustment** | Retry, reflection, action/activation/decision within episode; no effective cross-episode asset/policy change required | More calls/compute can improve score without learning or any durable self-change |
| **F1 · Persistent external asset** | Versioned, effectively promoted and installed SOP, skill, memory or executable procedural resource | Persistence ≠ model weight learning; human-authored asset ≠ autonomous self-origin; artifact must actually be used |
| **F2 · Persistent model/decision policy** | Installed learned parameter OR executable decision policy/selection rule changes across episodes | Storage location not by itself the classifier; switching to a stronger pretrained model ≠ self-learning; learned policy update ≠ meta-improver update |
| **F3 · Modified improvement operator** | The *improver* that proposes/selects/promotes later changes is itself effectively modified, installed and versioned under traceable authority | Structural operator change ≠ causally demonstrated **future improving ability**, unbounded recursion, or stronger cognition |

The tiers describe **modification loci**, not ordinal intelligence scores, not universally exhaustive or mutually exclusive for a multi-change experiment. **Independent component creation/retirement (M2) cannot be assigned F1 or F2 merely by name**; component identity/authority and scientific target boundaries must first be resolved. F0–F3 apply equally to no-LLM SOP, Jev-like typed selectors, weak LLM + genuinely non-LLM strong body, dynamic member systems, and feedback learning; no default cognitive-LLM requirement.

### Important lexical/scientific distinction

Some published work calls repeated system-version revision **recursive self-improvement** in the broad *system-level* sense (e.g. AIDE² and RRSI). SAR-04's **strong F3 future-meta-improver advantage** is a *stricter, proposed research claim*, **not** a universal redefinition that retroactively makes those authors wrong. Neither a paper's use of “RSI” nor repeated stronger target-task scores establishes `I_(g+1)` is a more effective updater.

## 3. Separate the improved target from its improver

Introduce **review-only measurement symbols**, not Core fields:
- `T_g`: target system/harness/SOP/model/policy (the *improvee*) at version g.
- `I_g`: installed and authorized improvement operator (proposal, selection and promotion policy) generating later changes to `T_g`.
- `E*`: fixed independent evaluator with decision-time/held-out separation.
- `T_(g+1)=Promote(I_g(T_g,H_g), E*)` is *a candidate update-loop representation*, not proof of any gain.
- **Structural F3** needs a verifiable `I_g→I_(g+1)` effective installed update, with actor/authority, executable semantics, hash/version and event lineage.

To claim **strong F3 causal value**, test `I_g` against `I_(g+1)` **on the same starting target version `T_g`**, with matched optimization budget, data access, compute, human cost and risk, on independently held-out **future** improvement tasks; score the future accepted target updates under the same immutable external evaluator, report failed edits, no-change, regression, rollback and uncertainties. This has **not been executed**.

**Key kill arguments:**
1. `T_(g+1)>T_g` at task score can arise with `I_(g+1)=I_g`; improved output/target ≠ improved improver.
2. A changed optimizer that was *proposed but not installed* is not an effective structural F3 change.
3. Changed evaluator/rubric, hidden future-answer access, unbalanced tokens/calls, task-memorization, external human-published SOP and stronger-model substitution can all produce **false RSI attribution**.
4. One effective optimizer change does not establish infinite depth of recursion or unlimited future improvements.

## 5. Scientific Program routing and strongest objection

The **PrimaryEstimand**, not “RSI”, routes the Claim:
- **SCF:** causal effect of installed SOP/policy/improver mechanism on a system-level property, with design/resource/manipulation controls.
- **SDR:** time/generation/version trajectory, improvement/forgetting/degradation, failure propagation, rollback and recovery.
- **ASR:** information-conditioned policy for where/when to learn, add/retire components, revise/stop/accept/rollback an update, including `NO_CHANGE`.
- **CSCI/X1/X2:** components' capability effect modification and transfer/generalization are crosscutting; they do not automatically create a fourth Primary Program.

**Strongest skeptical question:** A genuinely joint “improver-of-improver changes the system's future ability to improve” causal estimand may involve strategy, structure and dynamics, potentially unidentifiable if forced into a single existing Program. R5.1 `RA1/RA6` require theory/contract re-review *if* an independently specified irreducible `Q*` is found. This work unit supplies no such independent proof. Do not presuppose a fourth Program, nor claim the current three are mathematically irreducible.
